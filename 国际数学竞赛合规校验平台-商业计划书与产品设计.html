一、项目概述

1.1 一句话定位

面向国际学校 / 国际部，提供 HiMCM / MidMCM / MCM / ICM 参赛资格的自动化合规校验工具——输入学生信息，一键输出资格判定 + 合规报告 + 赛季提醒。

1.2 核心痛点

每年大量队伍因年龄误判（14.5 岁线）、跨校组队、advisor（指导老师）不合规等原因被取消资格，损失整个赛季的努力和升学材料。对一支 HiMCM 队伍而言，隐性投入远不止报名费：

  • 资金成本：赛前培训 3,000–8,000 元 / 队 + 注册费 100 美元 / 队（官方明确不予退还）[1]；
  • 时间成本：3–6 个月备赛周期，占用学生标化、校内 GPA 与申请文书的时间窗口；
  • 机会成本：HiMCM 结果次年 2 月底公布[1]，与美本申请材料季强耦合，一次失格意味着当年申请故事线断档；
  • 大学生端同样存在：MCM/ICM（美赛）获奖是国内高校推免 / 保研综测加分的重要认定项[3]，若因资格瑕疵被追溯取消成绩，保研认定同步失效。

更关键的是，规则本身正在快速变化：2026 赛季 HiMCM/MidMCM 更新了组队主体政策（同一学校 / 机构 / 官方批准的项目）、明确排除短期竞赛培训机构作为组队主体、禁止同一学生"两头报名"，并新增 AI 使用报告与在线投稿要求[2]——市场上的中文二手解读普遍滞后甚至自相矛盾，家长与老师缺乏可靠的"规则原文 → 可执行判定"的翻译层。

1.3 解决方案

轻量级 SaaS 工具：录入学生与队伍信息（出生日期、年级、学校 / 机构、advisor 身份），系统基于结构化规则库自动完成资格校验，输出三态判定（通过 / 风险 / 不合规）+ 逐条官方依据的合规报告 + 赛季关键节点提醒。全部校验逻辑对齐 COMAP 官方规则原文并做版本化管理，每个赛季更新规则包。

  1. 规则刚变，认知断层最大：2026 赛季 HiMCM/MidMCM 新增组队主体政策、排除培训机构、禁止两头报名、AI 使用报告与在线投稿新流程[2]——全市场需要重新学习规则，正是"规则翻译层"产品的引爆窗口。
  2. 赛季就在眼前：HiMCM/MidMCM 2026 赛季注册截止为美东时间 2026 年 11 月 4 日 14:00（北京时间 11 月 5 日凌晨 03:00），窗口 11 月 4 日 15:01 至 11 月 17 日 20:00（美东）[1]——距现在仅两周，痛点即时可验证。
  3. 参赛基数持续增长：HiMCM 中国队伍占比约 85%，美赛中国队伍 2.5 万支且保研认定需求刚性[3][5]。
  4. 数据合规倒逼工具化：《个人信息保护法》对未成年人信息的单独同意与最小必要要求，使学校与机构更倾向使用合规工具而非个人微信收集学生出生日期等信息。

3.2 十大高频失格判例（判例库种子）

  1. 年龄线误判：MidMCM 队伍中一名成员开赛时超过 14.5 岁（哪怕超几天）——整队应改报 HiMCM，误报将被取消资格。
  2. 跨校组队：普通情况下跨校拼队不合规；HiMCM 仅当全员属于同一官方批准的项目时才允许跨校；MCM/ICM 完全不允许跨校。
  3. 机构挂名：以竞赛培训机构名义组队——2026 新规明确此类主体不被认可。
  4. 两头报名：同一学生既挂本校队又挂机构队，二选一规则被违反。
  5. advisor 不合规：顾问非本校 / 本主体教职人员（外校老师、机构老师、家长挂名）。
  6. 学籍身份：已毕业学生或研究生出现在 MCM/ICM 队伍中。
  7. 窗口期换人：比赛窗口开启后变更团队成员名单。
  8. 匿名违规：论文出现学生姓名、学校名或顾问姓名（应仅含控制号）。
  9. 竞赛行为：比赛期间在社交媒体发布题目 / 解法，或向队外任何人（包括顾问）求助。
  10. 三段式截止混淆：注册截止、窗口关闭、提交截止是三个不同时点，错过提交截止同样可能导致取消资格或降级[1]。

3.3 三层规则模型（引擎架构的关键洞察）

中国市场的合规风险实际上是三层叠加，而现有解决方案只覆盖第 1 层的模糊版本：

  • L1 · COMAP 官方规则（失格级）：年龄线、组队主体、advisor、匿名、AI 政策——违反即取消资格，本平台的核心判定层。
  • L2 · 学校内部规则（门槛级）：例如部分高校要求"必须参加过全国大学生数学建模竞赛方可报名美赛"、"每队仅限 3 人必须三人组队"[4]——比官方更严，属于可配置校验项（学校面板自定义规则包）。
  • L3 · 报名通道规则（流程级）：辅助报名平台 / 机构的材料口径、时间节点与费用差异——作为提醒与提示层，不做硬判定。

这一分层让同一引擎同时服务 C 端（只跑 L1）与 B 端（叠加 L2/L3），是产品的可扩展性来源。

四、产品设计

4.1 产品形态与原则

  • 双端形态：Web 单页应用 + 微信小程序（家长端主入口）；另保留离线单文件版用于 B 端内网部署与市场演示。
  • 三分钟出报告：从录入到拿到判定不超过 3 分钟，无注册墙即可试用（付费解锁完整报告与提醒）。
  • 敏感数据最小化：出生日期等字段默认在前端本地计算，可开启"校验即焚"不留存。
  • 可解释性优先：每个结论都带官方依据，不做黑箱判定——这是与"问顾问"最大的体验差异。

4.3 校验引擎工作流

  1. ① 信息录入

    选择赛事（MidMCM / HiMCM / MCM·ICM）→ 录入成员（姓名拼音、出生日期、年级、学校 / 机构、学籍状态）→ 选择报名主体（本校 / 机构·项目）→ 选择 advisor 身份。

  2. ② 标准化

    出生日期换算为"以开赛时点计"的精确年龄（X 岁 Y 月 Z 天），并计算与年龄线的差值天数。

  3. ③ 规则匹配

    按赛事加载当前赛季规则包（L1 官方规则 + 可选 L2 学校规则）。

  4. ④ 逐项判定

    三态输出：通过（PASS）/ 风险（RISK，需人工确认或口径待官方确认）/ 不合规（FAIL，构成失格事由）；距离年龄线 ±60 天内自动升级为风险提示。

  5. ⑤ 报告生成

    报告编号 + 生成时间 + 判定明细 + 官方依据 + 建议动作（如"改报 HiMCM"或"邮件 himcm@comap.org 确认口径"）。

  6. ⑥ 存档与提醒

    保存队伍档案，订阅四段式赛季提醒；临近注册截止 7 天内黄色预警。

4.5 界面与交互风格

工具类页面采用白底淡蓝主色 + 紧凑布局 + 简洁线条图标，合规报告预览使用毛玻璃弹窗；判定结果用绿 / 橙 / 红三色语义色直观区分。界面与随附可运行原型完全一致（见 4.6），原型即 MVP 的视觉基线。

4.6 可运行原型（随本方案交付）

同目录文件《国际数学竞赛合规校验引擎-可运行原型.html》：单文件、零依赖、双击即可在浏览器打开。已内置 2026–27 赛季规则包，完整演示 F1（三态校验 + 年龄精确计算）→ F2（报告生成与打印导出）→ F3（赛季倒计时）→ localStorage 队伍档案管理 的核心闭环，可直接用于向学校与种子用户演示。

五、技术方案

5.1 总体架构：轻资产、可离线

  • 规则包：JSON 版本化管理（见 3.4），赛季粒度发布，前后端共用同一份规则源。
  • 校验引擎：纯前端本地计算（与原型同构），出生日期等敏感字段可不离开设备，天然满足"本地处理"卖点。
  • 轻后端：仅承担账号、支付、报告存证、提醒推送与学校面板；云函数 + 对象存储，边际成本近零。
  • 学校端：批量 Excel 导入 + 风险看板 + L2 规则配置；支持私有化单文件部署选项。

架构刻意避开重后端与大数据组件：单位边际成本 <5 元 / 队次，是 94% 以上毛利率的技术基础。

5.2 数据安全与隐私合规（PIPL）

  • 最小必要：仅收集姓名拼音、出生日期、年级、学校 / 机构名称；不收集身份证号、证件照片。
  • 未成年人特别保护：监护人单独同意流程；报告与档案默认 90 天自动删除，可选"校验即焚"。
  • 境内存储与加密：报告存证数据境内存储、传输加密、学校租户隔离；判例库仅保存脱敏案例。
  • 免责与溯源：平台输出为参考意见，规则最终解释权在 COMAP；每份报告附官方原文链接与规则包版本号。

5.3 MVP 范围与迭代路线

  1. 第 1–2 周

    规则包 V1 + 校验引擎（复用本次交付原型代码）。

  2. 第 3–4 周

    报告中心 + 分享 H5 + 微信提醒接入。

  3. 第 5–6 周

    小程序 + 支付（99 / 299 两档 C 端 SKU）。

  4. 第 7–8 周

    学校批量导入与风险看板 Beta（3,000 元首年种子价）。

  5. 迭代方向

    论文格式自查（25 页 / 匿名 / AI 报告 / ≤20MB）→ IMMC 等赛事规则包 → 多赛事矩阵。

6.3 成本结构与盈亏平衡

  • 第 1 年现金成本约 7–8 万元：服务器与域名 1.5 万 + 支付通道 0.3 万 + 内容与投放 4 万 + 合规杂项 1.5 万——首年即接近现金流打平（人力按创始人自研计）。

7.4 壁垒构建

  • 判例库：脱敏失格案例 + 官方往来邮件存档，越运营越厚。
  • 规则版本史：逐年 diff 与推送，构成"规则领域唯一连续记录者"的心智。
  • 学校采购绑定：年费制 + 看板工作流嵌入协调员日常。
  • 反向基础设施化：开放校验 API 给报名平台，把潜在竞争者变成渠道。
