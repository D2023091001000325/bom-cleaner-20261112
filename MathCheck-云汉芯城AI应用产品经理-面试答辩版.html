问题：资格误判 = 整季报废

国际数学建模赛道（HiMCM / MidMCM / MCM / ICM）每年有大量队伍因 14.5 岁年龄线误判、跨校组队、advisor 不合规 被取消资格——损失的是整个赛季的备赛投入与升学申请材料。而市场上"代报名"平台不做资格预审，"升学顾问"不懂 COMAP 细则，这个死角至今没有被产品化。

方案：把"资格"变成可计算的

我独立完成了 MathCheck：输入队员信息 → 规则引擎逐项判定（年龄/学籍/同校/advisor）→ 输出三态结论 + 可打印合规报告 + 赛季日历提醒。单文件、零依赖、双击即用，现场即可演示。配套 L1 免费判定器 / L2 单队付费 / L3 学校年费的三层商业设计。

02

问题定义：为什么是"合规"这个切口

产品经理的第一项能力，是从噪音里找出真需求。

核心用户：竞赛顾问

一位顾问同时带十几支队伍，批量处理是刚需；一旦某队资格出事，责任与口碑双输。他们要的是"名单级"的确定性，而不是单队咨询。

付费意愿最高 · L3 学校套餐的决策人

次要用户：家长

信息不对称带来持续焦虑：孩子生日够不够线？学校算不算同一所？他们缺的不是课程，而是一分钟内可读懂的判定结论。

L1 免费判定器的天然传播者

边缘用户：DIY 学生

普高国际方向、自组队参赛者，没人帮他们核对规则。路径分流（国内高考 vs 国际体系）决定了他该报哪个赛事，这正是 MathCheck 第一屏解决的问题。

口碑与内容传播的种子用户

需求判断：用户要的是"确定性"，不是"更好的辅导"

现有供给他们做什么留下的缺口
代报名平台（赛氪 / 数模乐园等）收钱、填表、走流程不做资格预审 —— 报名成功 ≠ 资格合规
升学顾问规划申请路径、文书懂申请、不懂 COMAP 具体规则细节
建模培训机构教建模、带刷题教建模不教合规，且客单价高
MathCheck（本项目）把规则变成判定引擎 + 报告补上"资格确定性"这一格
结论：这是一个渗透率接近 0 的增量市场——不是从竞品手里抢用户，而是把"没人做的预检"变成新品类。

产品方案：三层递进 + 一个入口

先给确定性，再谈商业化。

产品主流程：四步向导，全程不超过 2 分钟

STEP 1
选择路径
国内高考/强基 vs 国际体系 —— 决定可报赛事
STEP 2
选择赛事
MidMCM / HiMCM / MCM / ICM，按身份解锁
STEP 3
填写队伍
队员生日/学校/年级 + advisor 身份
STEP 4
合规报告
三态判定 + 逐项依据 + 可打印 PDF
现场 3 分钟演示动线：① L1 快速判定器输入一个生日 → 秒判可报赛事；② 选"国际体系 → 初中"进入 MidMCM，点"填入示例队伍"一键校验 → 全部通过；③ 把一名队员生日改成 2011-08-15（超龄）→ 判定翻红，报告标注"开赛日 15.2 岁，超出 14.5 岁线"；④ 打开"赛季日历"展示 11 月/1 月双赛季与春节标注；⑤ 点"打印 / 导出 PDF"展示报告即交付物。

L1 · 免费年龄判定器

只输入出生日期，秒判 MidMCM 是否达龄、HiMCM/MCM 适用性。承担获客漏斗：家长群、竞赛群转发成本为零。

L2 · 单队合规校验（99 元/次）

整队判定 + 同校检查 + advisor 提醒 + 报名倒计时 + PDF 合规报告。按次付费匹配"一年一次"的低频场景。

L3 · 学校年费套餐（3000–5000 元/年）

批量导入全校学籍 + 多顾问协同 + 赛季自动提醒 + 定制 FAQ。按校成交，拉高 ARPU，锁定续费。

核心功能设计（均已实现并可演示）

功能设计要点为什么这样设计
年龄判定引擎按 COMAP"出生线"口径：MidMCM 开赛日 ≤14.5 岁 = 不早于（赛季年−14）年 5 月 1 日；自动算到天，±45 天标"临界、建议官方复核"家长最容易被"差几周"坑；把临界态显性化，比给一个冷冰冰的通过/不通过更有用

Advisor 校验本校教职员 / 外校 / 机构 / 家长 / 学生逐一给判定与依据机构老师挂名是家长维权的重灾区，产品直接给"不可用"的明确结论

合规报告判定 + 逐项依据 + 队伍快照 + 日程，一键打印/存 PDF，带报告编号可追溯报告是"可交付物"：顾问可交学校、家长可留档，也是付费的理由

五个关键产品决策

面试官最想听的，不是"做了什么"，而是"为什么这么做"。

01

做"预检"，不做"代报名"

代报名是交易与履约，链条长、风险高、同质化；预检只对"资格确定性"负责，交付物是一份判定与报告。我选择切最痛、最窄、最容易验证的那一刀。

取舍逻辑：先建立"判断力"壁垒，再考虑向交易延伸
02

规则引擎数据化，拒绝黑盒硬编码

所有规则收敛为一套可配置口径：开赛日推算、报名截止、官方公告日期覆盖、出生线公式。规则会变（历年赛程有微调），产品必须跟着官方变而不用改代码。

面向"规则会变"的场景做产品，是 AI 应用产品经理的基本功
03

三态判定：宁可复核，不误杀

通过 / 需人工复核 / 不通过。二态会制造误杀（家长最痛），更多态则不可执行。临界出生、写法差异、特殊学籍一律进"复核"通道，并给出复核建议。

把"确定性"和"公平"同时交付，是这类产品的信任基石
04

用免费 L1 做漏斗，用学校套餐拉 ARPU

L1 判定器是天然传播节点（家长转发）；L2 按次付费匹配低频场景；L3 学校套餐把"批量+协同+提醒"打包成机构刚需。三层价格带对应三种决策人。

定价不是拍脑袋，是决策人 × 使用频次 × 决策半径的乘积
05

本地优先、零依赖交付

学生出生日期是敏感信息 —— 数据不出本机；同时零服务器成本让验证速度最快：一个 HTML 文件发给顾问即可试用，不需要说服对方"注册一个账号"。

冷启动期，交付摩擦就是最大的转化对手；隐私敏感场景下"本地"也是卖点
05

技术实现与工程取舍

产品经理不需要写最强的代码，但必须对实现边界有判断。

交付形态：一个 95KB 的 HTML 文件

  • 零依赖：原生 HTML/CSS/JS，无框架、无 CDN、离线可用
  • 本地存储：localStorage 保存队伍档案，刷新不丢
  • 原生能力：Blob 导出 .ics 日历、print CSS 生成 PDF 报告
  • 性能：全部判定在浏览器内完成，无网络请求，交互即时
取舍：没上 React/后端是有意为之 —— 冷启动期，验证"值不值得存在"比"架构是否优雅"重要 100 倍。

判定引擎伪代码

商业化设计（假设模型）

所有数字为公开信息推算的假设，用于验证商业逻辑是否成立。

市场底盘

  • 中国国际学校 / 国际部约 1200 所，G9–G12 在校生约 60 万人
  • 每年 HiMCM 参赛队伍约 1000 支（中国占 85%），MidMCM 增长更快
  • MCM/ICM 中国队伍约 2.5 万支（2026），其中留学意向大学生为次级市场
  • 合规校验渗透率 ≈ 0 —— 增量市场，教育成本在前、竞争压力在后

三层收入模型

层级价格角色
L1 判定器免费获客与传播（家长/学生）
L2 单队校验99 元/次转化（按次，低频友好）
L3 学校套餐3000–5000 元/年ARPU 与续费（顾问/学校）
  • 为什么是 99 元（四重锚定）：① 对标总投入——单队显性投入（培训费＋约 $100 注册费且不退）约 4000 元＋，99 元 ≈ 2.5%，是典型"保险型付费"：用户为"不被取消资格"付费，而非为软件付费；② 对标报名费——HiMCM 注册费约 $100/队（≈720 元），预检 ≈ 其 1/7～1/8，落在"报名前保险"的合理溢价区间；③ 心理关口——低于 100 元整数关口，降低家庭决策摩擦；④ 成本侧——临界案例人工邮件复核约 15–20 分钟，边际成本可控
  • 为什么是 3000–5000 元/年：单校年均 8–12 支队 × 99 元 ≈ 800–1200 元基础值 ＋ 批量导入 / 多顾问协同 / 自动提醒的效率溢价；对照顾问人工核对成本（约 30 分钟/队 × 10 队 ≈ 5 小时/年，时薪 150–300 元 ≈ 750–1500 元），套餐价约为人力替代成本的 2–4 倍，符合 B 端效率工具定价惯例
假设推演：1200 所学校 × 渗透 3% ≈ 36 所 × 4000 元 ≈ 14.4 万元/年（L3）；另有队伍级 L2 收入。该模型仅验证价格结构合理性，非收入承诺；与《商业计划书》中"99 元 ≈ 队伍投入 2.5%"的定价锚点口径一致。

合规报告（可打印/可追溯）结构化输出与留痕BOM 体检报告、询报价单、质量与溯源报告 —— B 端决策需要"可发给客户的文件"
赛季日历 + .ics时间履约与提醒交期承诺管理、备货与交付节点提醒、客户跟单触达
L1/L2/L3 定价免费引流 + 按次 + 年费平台会员分层、增值服务包设计（选型/合规/数据服务）
本地优先 / 零依赖隐私敏感 + 低成本交付客户 BOM 数据敏感场景的私有化预检、账号体系外的轻量工具获客

优先级排序：A（P0 首选）＞ B（P1 二期）＞ C（P2 三期）

若只能选一个，首选提案 A（BOM 合规体检）：① 规则引擎骨架可直接复用，落地最快；② EOL/停产料误购的赔付是确定性刚需，痛感最硬；③ 指标可量化（体检完成率 / 替代采纳率），价值最易被验证。提案 B 依赖 LLM 解析效果，不确定性更高，放二期；提案 C 偏体验与增长，放三期——与「Q7 预算只够做一个」的答案一致。

提案 A · BOM 一键合规体检 P0 首选

问题：客户 BOM 中混入停产（EOL）料、禁限用物质风险、无合规替代方案，往往是报价后才暴露，赔付与返工成本高。
方案：上传 BOM → 逐行校验（生命周期/合规/替代）→ 三态分级报告 → 直接联动替代料与报价。复用我验证过的"判定+报告"骨架，规则先于模型。
验证：历史订单回放 100 份 BOM，对比人工核验的一致率与耗时。
北极星：BOM 体检完成率 · 替代推荐采纳率

提案 B · 询报价智能匹配 Agent P1 二期

问题：RFQ（邮件/表格/图片）格式五花八门，人工拆行、匹配库存与价格，响应慢、改价率高。
方案：LLM 解析 RFQ → 结构化物料行 → 规则匹配库存/价格/交期 → 生成报价草稿（人工确认后发出）。与「配单—询报价」环节直接对齐。
验证：选取历史 RFQ 做回放，度量一次匹配成功率与报价时长。
北极星：报价时效 · 一次匹配成功率 · 改价率

提案 C · 选型知识助手（RAG） P2 三期

问题：工程师查数据手册、替代关系、行业标准，路径长；平台已有 4100 万+ SKU 与专业数据，价值未被充分利用。
方案：在 BOM 智选云表与选型页嵌入 RAG 问答：数据手册解读、参数对比、替代推荐依据，答案可溯源到规格书。
验证：A/B 灰度，度量问答采纳率与后续加购/转单行为。
北极星：回答采纳率 · 问答后转单率
说明：以上提案基于公开资料的产品推演，未经内部数据验证；入职后会以真实用户访谈与埋点数据重新校准优先级。

面试 Q&A 预案

我预判会被问到的 7 个问题，以及我的回答框架。

Q1为什么不做竞赛垂直产品，而来云汉芯城？›
我在 MathCheck 里验证的是"规则引擎 + 分级判定 + 报告交付"这套骨架。竞赛市场天花板低、合规渗透率为 0 需要长期教育；而云汉芯城有 83 万注册用户、真实的 BOM 数据与全链路场景，同一套能力在这里的价值密度高一个量级。我想在"数据密度最高、验证最快"的地方做 AI 产品。
Q2你没做过电子元器件，凭什么做这个岗位？›
三点：①已验证的交付能力——独立完成 0→1 产品上线、6 组 33 项测试断言、5 次自我纠错，产品能跑起来；②做过功课——我拆解了贵司半年报里的 AI 落地清单（HiBOM、BOM 智选云表、AI 备货预测）与"选型—配单—询报价—交付"链路，今天的三个提案就是基于公开信息推演的；③思维匹配——BOM 校验最需要的"规则确定性思维"，正是我在 MathCheck 里打磨的。
Q3这个项目最难的产品决策是什么？›
三态判定。二态会误杀（把"校区写法不同"判成跨校），家长最痛；四态以上用户无法执行。最终选择"通过 / 需复核 / 不通过"，并把临界出生、写法差异、特殊学籍统一送进复核通道 —— 在"确定性"和"公平"之间找到可落地的平衡。
Q4你如何给需求排优先级？›
三个维度相乘：痛点强度 × 可验证性 × 复用价值。先用能拿到数据验证的需求建立信任（BOM 合规体检），再做规模化的（询报价 Agent），最后做体验型/增长型的（知识助手）。不追求"AI 故事完整"，追求"每一步都能被指标检验"。
Q5怎么衡量一个 AI 功能是否成功？›
先定业务指标（时效、采纳率、转化率、复核率），再定模型指标（准确率、召回率）。没有业务指标的功能不上线；上线后按周看灰度数据，复核率是我特别关注的指标——它同时反映模型边界和用户信任度。
Q6LLM 在你的产品里应该做什么、不该做什么？›
判定必须可解释、可追溯，由规则与数据承担；LLM 负责解析（RFQ/规格书）、解释（为什么不能替代）、对话检索（RAG）、文案生成。像"资格认定/合规结论"这类错判代价高的决策，不让模型独立承担——规则兜底，模型增强，人审兜底。
Q7如果预算只够做一个 AI 功能，你选哪个？›
BOM 合规体检。理由：确定性最高（规则可验证）、能复用我验证过的判定+报告骨架、直接服务"配单—询报价"转化、且报告天然可交付给客户 —— 最短路径上同时拿到"体验价值"和"商业价值"。
